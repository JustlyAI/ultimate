Reports failed runs to their subagent owner or @ultimate.

Provider errors classified as temporary by Pi, and Claude Code relay responses that ended incomplete with status 200 or unknown, get one continuation after 60 seconds. A run that failed because its provider's host was unreachable (`ENOTFOUND`, `EAI_AGAIN`, `ECONNREFUSED`, `ECONNRESET`, `ENETUNREACH`, `EHOSTUNREACH`, also inside a Claude Code relay failure) waits for the network instead (`unreachableEndpoint` in `server.ts`): watchdog opens a TCP connection to that host, and while it fails, adds a quiet `watchdog.offline` note to the conversation and probes again after the time already waited, at least 30 seconds and at most 10 minutes. Nothing tells a process portably that the network is back, so the probe is the event; the growing interval keeps a long outage cheap. Once the host answers, the run gets its usual continuation, so a scheduled run that fired offline resumes after reconnect; a run that failed again while the host was reachable is reported as usual. After 6 hours unreachable it is reported, with a hint to resume it once the network is back. A broken login (“not logged in”, a failed OAuth refresh, `invalid_grant`) is reported at once with a hint to log in again that names the provider (`diagnose` in `server.ts`). If someone has resumed the conversation and it is busy at that deadline, watchdog leaves it alone. `subagent stop` cancels that child's pending watchdog task and withdraws any queued retry input, using the stop handler's captured identities so replay leaves later work alone. A failed retry is never retried again. Persistent and non-temporary errors become a `watchdog.failure` card with the conversation, title, error, last tool step and any login hint; reporting a subagent's failure marks its parent's `failed` action for it `given-up`. @ultimate's own failure raises a notice instead. User Stops are ignored; reply-expecting Messages inputs already have a failure reply and are excluded.

A root receipt and background task are created atomically for each failed generation; retry/report submissions use stable request IDs. On open, missed failures are scanned above the stored high-water mark, never advancing past unfinished work. Fresh installation marks existing tasks as historical and reports none of them.

Older transcripts may hold `watchdog.idle` notes from a retired idle-branches reminder; they still render. What each branch waits on now shows in the sidebar (`lib/waits.ts`).

Watchdog keeps the last 20 reported failures (`watchdog.reported` on the root, written with each report, including @ultimate's own) and serves them through `WatchdogApi.failures(since)`, newest first; the `status` extension reports them.
